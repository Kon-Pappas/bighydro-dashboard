# Tests

Two suites, both run in CI (`.github/workflows/tests.yml`) when code or tests change. They never run on the daily data commits, and a failing test never blocks the daily update.

## Pipeline (Python) — `python tests/run_all.py`
Needs `pandas numpy requests openpyxl xlrd` (see `requirements.txt`). Exit code is non-zero if any check fails. Fixtures are built in memory (synthetic ADMIE workbooks and ENTSO-E XML); no network, no repository data are read.

## Page (JavaScript, jsdom) — `node tests/dashboard/run.js`
First `npm install --prefix tests/dashboard`. The badge checks («only the MCP missing» / «missing sources») use two **fixed past days whose status is forced** in the test (`OVR`, D99) and first assert that they exist, so they cannot vanish when the real data change. The inflow panel (TEST 21) is tested against a **synthetic `inflow_climatology.json`** supplied through the same `OVR` table: cards, panel, chart, regime colours, the period (Monday to Sunday), the Ilarionas and low-confidence notes, the alternative-baseline sentence, Greek and English, a river missing from the file, and the page without the file. Mutation-checked with 9 faults. TEST 22 covers the generation section, the per-river generation panel and the **inflow scenarios** (synthetic `energy_climatology.json`, expectations recomputed in the test from `unit_daily.json` and the model stock): the five scenarios × two rates, « does not run out », « > 1,000 days », the projection chart (end point = stock + 56·(inflow − rate), floored at zero, the usual-stock band by calendar week), a missing or too old « recent », the notes, Greek and English, and the page without the file. Mutation-checked with 17 faults. The older tests count only the content outside these sections (`own()`). TEST 23 covers the *Last / Next Update* from a synthetic `meta.json` (the cases are run with a fixed « now »: today, « (tomorrow) » by the Athens calendar date and not by +24 hours, later dates, a run already in the past, summer time, the night before the autumn change and the 25-hour day), the page without the file, Greek and English, and that **every data request carries `cache: 'no-cache'`** (the harness records the options of each fetch). Mutation-checked with 12 faults. TEST 24 covers the **visible-hydro card** when RESMV is partial or missing (three fixed days with the RESMV status forced by the test; the expected total is recomputed from the day file): « ≥ » and « RESMV is incomplete (19 of 24 hours): the total is a lower bound », the unchanged card of a complete day, a day without RESMV, Greek and English. Mutation-checked with 6 faults. The test loads the real `index.html` and the real JSON files in `data/` into jsdom and checks that tabs, cards, charts, tables, both languages and the numbers shown agree with the data files; it also covers the shell (breadcrumb, Last/Next Update, language defaults, the GR | EN switch and the shared `kp_lang` key, badge and banner, footer), the loading overlay **with its real pauses** (steps appear in order, "ready" only after the last one), the modals (fixed header/footer structure, ✕, Close, Escape, backdrop), the clickable-card cues, the date navigation inside the river modal (select, previous/next, arrow keys, limits) the pumped-storage section (cards, rolling chart, stacked bars and tables recomputed from `psh_daily.json`, graceful absence) the unit-availability section (flags, zero-day counts, last normal day, chart, selector, modal warnings, graceful absence), the comparison with previous years (percentiles and ranks recomputed from the raw ENTSO-E files), days of cover (rates, days, usual stock, trend and inflow equivalent recomputed for two dates), the Ilarionas + Polyfyto sum line, the confirmed Nestos pump direction, and the tooltips on every chart. It therefore depends on the repository data: the "today" cases (a day with reservoir levels but no SCADA, and a day with only ISP) are built as **synthetic days** appended after the last real one, so the result does not depend on the time of day; the other assertions are written to be **dynamic** (recomputed from the files) rather than fixed numbers, so they keep passing as new days arrive. Keep it that way when adding checks.

**Mobile (TEST 25, D110).** jsdom does no layout, so the page test checks the mobile rules in the one `max-width:767px` block (no header line, 12 px gaps, the secondary box and its 40 px wells, tabs 3 + 2 at 48 px, the ↑ button), the short labels in both languages, that the ↑ button sits before the script that wires it, and its show / hide / back-to-top behaviour with a stubbed position of the tabs. The heights themselves (first content at 360 and 320 px) are measured in a real browser (Playwright) before every zip and written in DECISIONS.

## Not covered
Real browser rendering (charts are checked as SVG markup, not pixels; mobile heights are measured with Playwright by hand, see TEST 25 above), live ADMIE/ENTSO-E responses (only synthetic samples), `calibrate_energy.py` (run manually and reviewed by eye).

## Adding a test
Pipeline: add a function to the closest file and use `check(name, condition, extra)`; keep the final `sys.exit`. Page: add a `ck(name, condition, extra)` line to `tests/dashboard/run.js`.

**Rounding in the page tests.** Some JSON files store a value with one decimal (e.g. `climatology.json`) and the page shows a whole number. A test that recomputes the exact value from the raw files therefore compares with `near`/`nearEq`/`nearRange` (±0.25 GWh around the exact value: the storage precision), never with equality of two separately rounded numbers (D89, K25).

**Fixtures must have the real structure.** The first clock-change diagnose passed its tests but reported a 50 % loss on ordinary days because its simulated files had no daily-total column, which the real files have. A test file must reproduce every column and row type seen in the real file, and an ordinary case must be asserted to report no anomaly.

**A test that cannot fail proves nothing.** When a new module passes all its tests on the first run, break it on purpose (a mutation) and check that the tests fail. Disable bytecode caching while doing so (`python -B`, delete `__pycache__`): two edits of the same length written within the same second keep the old `.pyc`, and the mutation is silently not applied.
