# Decisions log

Format: **what** · *why* · alternatives rejected. Dates are approximate (the project ran from September to October 2026). Newest decisions last.

| # | Decision | Why / what was rejected |
|---|---|---|
| D01 | One JSON file per day plus derived files | Cheap re-runs and small diffs. Rejected: one large `hydro_data.json` (frozen legacy copy was removed). |
| D02 | `null` ≠ `0`; a new `null` never overwrites a value, a new value always does | Safe merging of partially published days; wrong data are repaired by re-running. |
| D03 | Store everything on **Greek local time**; shift ISP and MCP by +1 h | One clock for the page; verified on 288 days (median correlation 0.984). Rejected: keep each source on its native clock. |
| D04 | Lookback of 4 days on every run | Late ADMIE files heal on the next run without manual action. |
| D05 | Volume = fill % × capacity from the Stefanakos PDF; keep ADMIE's official total separately | Official total is volume-weighted and our rebuild is 0.98 pp lower; both are shown. |
| D06 | ENTSO-E weekly value = mean of end-of-day readings (Monday+1 … +7) | Best fit by far; an earlier "end of week" conclusion (from summer data only) was wrong. |
| D07 | Cascade model (sum of downstream plant factors) fitted by NNLS; report energy per **river**, not per dam | Per-dam factors are not identifiable (synthetic test). A single factor was 4.5× worse. |
| D08 | Two energy numbers: "ENTSO-E equivalent" (primary, calibrated) and "physical estimate" (gross head); Aoos shown separately | Owner agreed; they answer different questions and the page says so. |
| D09 | Gross head (not net) in the physical estimate | Data prefer it (κ = 1.005 vs 1.127). |
| D10 | Pigai Aoou is excluded from the ENTSO-E equivalent | Data show 0–200 MWh/hm³, not ≈ 1,795. Rejected: an unofficial document's claim. Revisit when more autumn data or ADMIE methodology is available. |
| D11 | 0.00 % readings on large dams are interpolated in calculations only | Ilarionas read 0.00 % for 19–25 July (63 hm³). Raw files stay untouched; the banner explains. |
| D12 | The water balance is called **apparent inflow** | It includes unmeasured withdrawals and losses; it must not be read as a flow measurement. |
| D13 | Sfikia and Asomata form one group in the balance | The pump cancels algebraically; avoids using the uncertain pump estimate. Proven and tested. |
| D14 | Ilarionas stays a separate group, with a caveat | Owner: the unit is faulty and must not be merged with Polyfyto. The split is unreliable while it does not turbine; the sum and the river total are unaffected. |
| D15 | Pumping per plant = SCADA total split by hourly ISP share (day share as fallback), always labelled *estimate* | SCADA/ENTSO-E have no per-plant pumping. DAM/intraday prices are deliberately **not** mixed in (owner: ISP vs SCADA is enough). |
| D16 | "Visible hydro" = TOTAL HYDRO + RESMV small hydro + Aulaki; RESMV flagged as an uncertified estimate | All small hydro (RESMV + PPC small + Aulaki) are ≈ 12 % of visible generation; RESMV alone reaches 21 % in April. |
| D17 | Kastraki > 100 % is normal and not flagged; a dedicated Kastraki tab tracks it | Owner knowledge; will matter when Amfilochia starts. |
| D18 | No pipeline changes for daylight-saving handling before 26 Oct 2026 | We have one real sample (29–30 March) and the effect is recoverable by re-running the day. |
| D19 | Recalibrate only on evidence (two weeks > 10 GWh out of sample) or in December | Factors moved ≤ 0.3 % when week 41 was added. |
| D20 | The page has no external libraries (SVG charts, vanilla JS) | Fully testable offline. To be revisited together with the shared look of all dashboards (Chart.js tooltips were proposed). |
| D21 | Scope: this repository is handled in its own threads; the other dashboards and the shared shell are separate work | Keeps context clean; everything needed to continue is in `docs/`. |
| D22 | `stored_energy.json` and the unused legacy files were retired | The page computes weekly/daily energy itself; fewer files to keep consistent. |
| D23 | Look and feel follows the other dashboards: dark slate base, breadcrumb to the hub, title, Last/Next Update, loading overlay, footer. The **accent colour is per dashboard**: BESS emerald, Gas-Power blue, Flows cyan, **BigHydro violet** (`--acc`, one CSS variable) | The house style is a shared base with one accent per site; violet keeps the four hub cards apart. Rejected: the previous light theme with automatic dark mode. |
| D24 | **English by default** with a Greek toggle; the preference is stored under the shared key `kp_lang` (all dashboards share one origin and can adopt it); the old key `bh_lang` is still read | Matches the other dashboards; a visitor's choice can follow them across the hub. |
| D25 | Charts stay hand-written SVG; **hover/touch tooltips with a crosshair** were added (no library) | Chart.js could not be checked visually in the test environment, while SVG was verified chart by chart; the user benefit (tooltips) is the same. Supersedes part of D20; revisit with the shared-shell work. |
| D26 | The banner and the "Complete/Partial data" badge consider only the sources the page uses: reservoir, SCADA, ISP, RESMV. MCP (price) is left out | Prices are not shown anywhere on this page. |
| D27 | "Next Update" is computed from the run times listed in `RUN_TIMES` in `index.html` (07:15, 09:15, 10:15 Athens) | Must be edited if the scheduler changes (for example a 13:30 safety run). |
| D28 | The footer repeats the owner's signature used on the other dashboards, plus data sources, a disclaimer and a link to this repository | Consistency with the hub; the disclaimer matters here (RESMV uncertified, estimates). |
| D29 | The loading overlay shows **real, sequential steps** with deliberate pauses: reading the files (at least 0.65 s), then one row per tab (0.35 s each), then "Dashboard is ready!" (0.65 s) — about 3.5 s on every load. Users who prefer reduced motion get shorter pauses (about 1.2 s). `window.__BH_FAST` removes the pauses for tests | The first version flashed by too fast to read (owner feedback); the BESS dashboard uses the same pattern. |
| D30 | The language control is a two-option segmented switch **GR \| EN** with the active option highlighted | Same pattern as the BESS dashboard; both options are visible at all times. |
| D31 | The methodology modal is titled **Methodology & Assumptions** and has two parts: the methodology paragraphs and a list of eight key assumptions | The title promised assumptions that were previously scattered inside the text. |
| D32 | Both modals (methodology and river cascade) have a **fixed header** (title and a boxed ✕), a **scrolling body** and a **fixed footer** (boxed Close). Escape and a click on the backdrop also close them; the page does not scroll behind an open modal. Heights use `dvh` with a `vh` fallback so phones are handled | Owner feedback; the text scrolls between two fixed parts on desktop and mobile. |
| D33 | River cards that open the cascade view look **raised** (gradient, border, shadow, lift on hover), carry a circular chevron and the cue **"View cascade ›"**; the combined Agras/Edessaios card, which opens nothing, is **flat with a dashed border** | Owner feedback: it was not obvious which cards can be clicked. The cue is always visible, so it also works on phones where hover does not exist. |
| D34 | The river modal's header holds the **date selector with previous/next-day buttons** (no ✕; the footer Close is enough). Changing the day inside the modal keeps it open on the same river and reloads the whole page behind it; the left/right arrow keys do the same on a keyboard (only while the river modal is open and no field is focused). The scroll position of the body is kept | Owner feedback: leaving the modal to change the date for every comparison would make users give up. The methodology modal keeps its ✕. |
| D35 | The date selectors, the river-modal day navigation and the default day offer **only days that have reservoir levels**. A request for another day (for instance the newest day early in the morning) falls back to the latest available day and shows a notice. The page tests build their "today" and "day without reservoir levels" as **synthetic days**, so they no longer depend on the time of day | On 2026-10-17 the CI failed: the newest day in `index.json` had been created by the ISP file (≈ 00:25) but the reservoir levels are published only ≈ 08:35, and selecting that day crashed the page. Every morning has this window. |
